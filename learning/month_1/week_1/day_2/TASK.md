# D2 任务书：测试用例的表示与查询

> 背景：你是测试工程师，手里有 5 条手工写的测试用例。今天的目标是把它们变成"程序能查询的数据"，并提供两个查询函数。这是最终项目"需求文档与测试用例助手"的第一块砖。
>
> 建议用时：数据 30 分钟，函数 90 分钟，验收 45 分钟，记录 15 分钟。

## 第一部分：数据（cases.py 顶部）

在 `learning/month_1/week_1/day_2/cases.py` 顶部定义一个列表 `CASES`，包含 **5 个字典**，每个字典是一条测试用例。

字段要求（5 条字典的键名必须完全一致）：

| 键 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | 用例编号，如 `"TC-001"`，互不重复 |
| `title` | 字符串 | 用例标题，5 条互不相同 |
| `priority` | 字符串 | 只能取 `"高"` / `"中"` / `"低"` |
| `steps` | 字符串列表 | 操作步骤，每步一个元素，至少 2 步 |
| `expected` | 字符串 | 预期结果 |

分布要求（后面验收要靠它保证结果可预期）：

- 恰好 2 条 `"高"`、2 条 `"中"`、1 条 `"低"`
- 至少 1 条标题含空格或英文单词（练字符串处理）
- 至少 1 条 `steps` 有 3 步以上

示例（这一条可以直接用，剩下 4 条自己编，主题任选：搜索、导出、上传、注销……）：

```python
{
    "id": "TC-001",
    "title": "正确密码登录成功",
    "priority": "高",
    "steps": ["打开登录页", "输入已注册的用户名和密码", "点击登录"],
    "expected": "跳转到首页，右上角显示用户名",
}
```

## 第二部分：两个函数（同一文件）

### 1. `filter_by_priority(cases, priority)`

- 输入：用例列表、优先级字符串
- 输出：满足该优先级的所有用例组成的**新列表**（字典原样放进去）
- 要求：
  - **不得修改传入的 `cases`**（这正是今天 verify Q2 考的副作用问题）
  - `priority` 不是 `"高"/"中"/"低"` 时，返回空列表还是报错？**自己决定**，把理由写成函数开头第一行注释
- 必须会两种写法：`for` 循环 + `append` 的朴素版，和列表推导式版（两个都写出来，朴素版注释掉或都保留）

### 2. `find_by_title(cases, title)`

- 输入：用例列表、标题字符串
- 输出：标题**完全等于** `title` 的那一条用例（一个字典）；找不到返回 `None`
- 进阶（可选）：再写 `find_by_keyword(cases, keyword)` —— 标题**包含**关键字即命中，忽略大小写，返回列表（提示：`s.lower()`；想想 `in` 怎么用）

## 第三部分：验收（文件末尾）

加 `if __name__ == "__main__":`，依次执行并自查：

1. `filter_by_priority(CASES, "高")` → 必须正好 **2 条**
2. `filter_by_priority(CASES, "低")` → 必须正好 **1 条**
3. `find_by_title(CASES, "正确密码登录成功")` → 返回 TC-001 那条
4. `find_by_title(CASES, "不存在的标题")` → 返回 `None`
5. 边界自查：
   - `filter_by_priority([], "高")` → 返回 `[]`，不崩溃
   - 调用 `filter_by_priority` **前后**各 `print(len(CASES))` 一次，都是 5 → 确认没改坏原数据
6. 用 `for` 循环把"高"优先级用例的 `title` 逐行打印（推导式版可加分，但先会写 for 版）
